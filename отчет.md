# Отчёт по практической №1

## 1. Вариант и масштаб

| Поле | Значение |
|---|---|
| ФИО (как в VK Education) | Иван Константинов |
| Вариант (запрос) | Вариант 2, Q10 |
| Масштаб `sfN` | sf1 |
| Почему выбрал такой масштаб | На Mac 8 ГБ памяти. Для sf1 хватает ресурсов, при этом в lineitem около 6 млн строк. |

## 2. Поднятые сервисы - и почему именно они

| Сервис | Роль в стеке | Почему именно он (а не альтернатива) |
|---|---|---|
| Silo, форк MinIO | S3-совместимое хранилище файлов | Работает локально, предоставляет S3 API для Trino и Spark. |
| PostgreSQL | БД метаданных Lakekeeper | Хранит состояние каталога в отдельной БД; строки TPC-H лежат в S3. |
| Lakekeeper | Iceberg REST Catalog | Trino и Spark находят через него таблицы Iceberg. |
| Trino | SQL-движок для загрузки и запросов | Поддерживает Iceberg и содержит генератор TPC-H. |
| Spark | Дополнительный движок для чтения Bronze | Читает те же таблицы без переноса данных в другую БД. |

### Скрипты, которыми поднимал стек

```sh
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"

# Хранилище файлов
docker run -d --name lakehouse-minio \
  -p 127.0.0.1:9000:9000 -p 127.0.0.1:9001:9001 \
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  -v minio-data:/data \
  pgsty/silo:RELEASE.2026-09-03T13-18-01Z server /data --console-address :9001

# База метаданных каталога
docker run -d --name lakehouse-pg \
  -e POSTGRES_PASSWORD=postgres -p 127.0.0.1:5433:5432 \
  -v pg-data:/var/lib/postgresql/data postgres:17.6-alpine

docker exec lakehouse-pg pg_isready -U postgres

# Подготовка базы Lakekeeper
docker run --rm \
  -e 'LAKEKEEPER__PG_ENCRYPTION_KEY=This-is-NOT-Secure!' \
  -e 'LAKEKEEPER__PG_DATABASE_URL_READ=postgresql://postgres:postgres@host.docker.internal:5433/postgres' \
  -e 'LAKEKEEPER__PG_DATABASE_URL_WRITE=postgresql://postgres:postgres@host.docker.internal:5433/postgres' \
  quay.io/lakekeeper/catalog:v0.14.0 migrate

# Каталог Iceberg
docker run -d --name lakekeeper \
  -e 'LAKEKEEPER__PG_ENCRYPTION_KEY=This-is-NOT-Secure!' \
  -e 'LAKEKEEPER__PG_DATABASE_URL_READ=postgresql://postgres:postgres@host.docker.internal:5433/postgres' \
  -e 'LAKEKEEPER__PG_DATABASE_URL_WRITE=postgresql://postgres:postgres@host.docker.internal:5433/postgres' \
  -p 127.0.0.1:8181:8181 quay.io/lakekeeper/catalog:v0.14.0 serve

curl http://localhost:8181/health

# SQL-движок
docker run -d --name trino -p 127.0.0.1:8080:8080 \
  -v "$PWD/catalog:/etc/trino/catalog:ro" \
  -v "$PWD/catalog/settings/jvm.config:/etc/trino/jvm.config:ro" \
  -v "$PWD/catalog/settings/config.properties:/etc/trino/config.properties:ro" \
  trinodb/trino:476

curl http://localhost:8080/v1/info
```

Команды создания бакетов и warehouse приведены в [README](README.md).
Настройки Trino находятся в [catalog](catalog/).

## 3. Разбор запроса - какие данные нужны

| Таблица TPC-H | Нужные колонки | Что запрос с ними делает (фильтр / джойн / агрегат / вывод) |
|---|---|---|
| customer | custkey, nationkey, name, acctbal, address, phone, comment | Связь с orders и nation, группировка и вывод данных клиента. |
| orders | orderkey, custkey, orderdate | Связь клиента с позициями, фильтр по IV кварталу 1993 года. |
| lineitem | orderkey, extendedprice, discount, returnflag | Связь с orders, фильтр returnflag = R, сумма цены после скидки. |
| nation | nationkey, name | Связь с customer и вывод страны. |

## 5. Тесты производительности

| Сжатие на Bronze | Время запроса | Размер Bronze, МБ | Твой вывод (что лучше и почему) |
|---|---|---|---|
| GZIP | 1,213 с | 191,424 | Меньший размер Parquet, но запись четырёх таблиц заняла 19,906 с. |
| ZSTD | 0,712 с | 196,814 | На 5,4 МБ больше, зато запись заняла 11,936 с. Для основных слоёв выбрал ZSTD. |

В таблице сравнивается Parquet. Q10 выполнен два раза на каждом варианте. В таблице указано время второго прогона.
Время получено из `system.runtime.queries`.
Размер получен по файлам данных четырёх таблиц Bronze, 1 МБ = 1 000 000 байт.
Сравнение с ORC и результат Q10 приведены в [results.md](results.md).

## 6. Часть 2 - осмысление и работа с инструментами

### 6.1. Понять и объяснить

| Вопрос | Твой ответ |
|---|---|
| Зачем нужны большие данные и lakehouse (а не обычная БД/хранилище)? | Lakehouse позволяет хранить файлы в S3 и читать их разными движками через таблицы. Iceberg добавляет схемы и снапшоты. Для маленькой обычной БД такая архитектура может быть излишней. |
| Пример schema evolution на Silver: добавил/переименовал колонку - что произошло? | В silver.demo.customer_evolution добавлена source_system, затем переименована в origin_system. Три старые строки сохранились, новая колонка содержит NULL. |
| Пример скрипта восстановления данных из снапшота (time travel) | `ALTER TABLE silver.demo.recovery_orders EXECUTE rollback_to_snapshot(3512653163815087150);` После удаления 20 строк осталось 0, после восстановления снова 20. Чтение `FOR VERSION AS OF 3512653163815087150` также вернуло исходные строки. |

### 6.2. Подключить инструмент к lakehouse

| Инструмент | Почему выбрал именно его |
|---|---|
| Spark 3.5.3 в Docker | Поддерживает Iceberg и позволяет проверить чтение Bronze вторым движком без копирования таблиц. |

Подключение задано в [spark/spark-defaults.conf](spark/spark-defaults.conf).
Команды для чтения Bronze находятся в [spark/read_bronze.sql](spark/read_bronze.sql).
Библиотеки Iceberg скачаны командами из [README](README.md).

```sh
docker stop trino
docker run --rm -e AWS_REGION=us-east-1 \
  -v "$PWD/spark:/opt/pr1:ro" \
  apache/spark:3.5.3 /opt/spark/bin/spark-sql \
  --master 'local[2]' --driver-memory 768m \
  --properties-file /opt/pr1/spark-defaults.conf \
  --jars /opt/pr1/jars/iceberg-spark-runtime-3.5_2.12-1.7.1.jar,/opt/pr1/jars/iceberg-aws-bundle-1.7.1.jar \
  -f /opt/pr1/read_bronze.sql
docker start trino
```

В консоли Spark получен список таблиц Bronze, подсчитаны строки и выполнен Q10.
Количество строк и все 20 клиентов совпали с результатом Trino. Вывод приведён в [results.md](results.md).

## 7. Выводы

Bronze сохраняет исходные таблицы, Silver отбирает нужные данные, Gold содержит готовый результат.
Для Q10 получено 20 клиентов, результат совпал с запросом на исходном TPC-H.
Для Parquet GZIP дал меньший размер, а ZSTD быстрее записался и выполнил повторный Q10. Разница в размере небольшая, поэтому оставил ZSTD.
Изменение схемы, восстановление из снапшота и чтение Bronze через Spark были проверены на этом стенде.
